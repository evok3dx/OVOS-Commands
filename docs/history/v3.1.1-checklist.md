# Jarvis 3.1.1 incident record · HISTORICAL

This page is a privacy-safe history of the V3.1 trial and the fixes that led
to 3.6. It preserves causes, decisions and regression gates, not raw logs,
user paths or hardware identifiers. Current publication status lives in the
[3.6 release checklist](../v3.6-release-checklist.md).

## Status convention

- **VERIFIED**: code plus an automated or recorded live result supports it.
- **PLANNED**: useful follow-up evidence, not a completed claim.
- **HISTORICAL**: failed or superseded approach retained for context.

## Installer and stack incidents

| Incident | Cause | Durable correction |
|---|---|---|
| Services returned `203/EXEC` after upgrade | Console-script shebangs still pointed at a deleted staging environment; manual editing later produced zero-byte launchers. | Build a clean staged environment, relocate every reviewed console launcher to the permanent virtualenv, reject temporary/root paths and retain the previous environment for rollback. |
| New OVOS core with broken native intents | A partial upgrade kept an older Adapt parser without the conversion method required by the newer Workshop. | Pin and validate the complete reviewed stack, then run a real parser-conversion probe before switching. |
| Wake plugin loaded no usable model | The default TFLite path was incompatible with the selected NumPy runtime. | Select the explicit reviewed ONNX model and prove it loads. Keep the metadata warning visible. |
| Listener was active but speech was unusable | One microphone backend opened successfully yet delivered unusable capture, so its fallback never ran. | Use the reviewed SoundDevice default with ALSA fallback only when no explicit user choice exists. Preserve selected devices. |
| Required packages or models were missing from V3 | The earlier release preserved an old environment instead of reproducing the tested set. | Stage all manifest-listed packages; prepare wake, Whisper, voice and Qwen models before changing Jarvis files. |

## Listening and feedback incidents

| Incident | Cause | Durable correction |
|---|---|---|
| Listening beep clipped or background sound stayed lowered | Ducking began before cue completion and restoration used a service-start volume snapshot. | Keep capture nonblocking, use cue completion only for duck timing, snapshot volume per activation and retain record-end plus fail-safe restore. |
| Quiet input became `Pause music` | A short false STT result was treated as real speech. | Keep the valid command; isolate cue audio, enable supported VAD filtering and require evidence before adding a blacklist or threshold. |
| Silence did not say “Please repeat” | This was intentional; empty capture should be quiet. Broad fallbacks also claimed some real unmatched commands. | Keep empty/wake-only input silent. Place narrow unmatched-command feedback after native/Media/Qwen routes and before broad fallbacks. |
| Startup said “I am ready” twice | Different historical stacks could load the boot-finished skill twice. | Install and validate the reviewed stack as one set; do not patch a working host based only on stale cache entries. |

## Command workflow incidents

| Incident | Cause | Durable correction |
|---|---|---|
| “Read this” reported no selection while reading continued | The dispatcher waited for the long-running helper process rather than a start result. | Return a bounded start outcome separately from ongoing playback. |
| 2× remained active | Delayed startup could outlive failure handling or the prior speed was not restored. | Treat 2× as a transaction, terminate late starts, restore the exact prior speed and clear the marker. Ordinary reading preserves manual speed. |
| “Read this” became “Write this” | Whisper confused similar short phrases. | Retain several strict reading variants and bounded Qwen reading actions; do not silently reinterpret selected target or speed. |
| Writing lost early words | Listening-cue completion had been coupled to capture. | Restore upstream nonblocking capture and keep cue completion limited to playback ducking. |
| Wake phrase appeared in continuous dictation | Speech Note's machine-owned rules were not part of the portable setup. | Preserve all rules and guide one additive case-insensitive regex covering comma and optional final punctuation. |
| Hermes/Claude message starters were brittle | Exact starters existed but natural variants were missing from Qwen's catalogue; one prompt also sent keys before focus was verified. | Keep native fast paths plus bounded semantic starters. Focus, open a new chat where appropriate, say “Ready”, capture once, recheck focus, send once and say “Message sent”. Qwen never sees the message body. |
| Browser prompt asked but did not submit | Conversation state was cleared immediately before activation, so another fallback received the reply. | Create one prompt state, retain the original focused window, consume one reply, recheck focus, type and press Enter without confirmation. |
| Media title reached Alerts or failed after Qwen approval | Media ran after Padatious, and dispatch reapplied a native-only parser to a model-approved title. | Run narrow Media title matching after native Adapt and before Padatious. Accept a bounded title only after Qwen selects `media.search`. |
| Speech Note read lock looked like startup failure | One exit code represented both conditions. | Give active lock, empty selection, startup failure and timeout separate codes and feedback. |

## Application and GUI incidents

| Incident | Cause | Durable correction |
|---|---|---|
| All detected apps were ticked | A carried `all-detected` policy was preserved correctly but looked like a fresh default. | Fresh setup defaults to Recommended and offers exactly Recommended, All and Custom. Updates preserve the user's saved choice. |
| Core-only left an empty app page | A retired setup mode remained visible through upgrade. | Remove it from current setup and direct old configurations to review. |
| Generic app names were ambiguous | Notes/Mail/Calendar mappings were implicit and could collide with multiple enabled apps. | Add compatible preferred selectors for Browser, Notes, Mail, Calendar and Office. One generic alias has one owner. |
| Tray did not return from the menu launcher | The launcher opened only the Control Centre. | Start the existing combined tray idempotently, then open the Control Centre. |
| Updates and health were hard to scan | Maintenance mixed version controls with diagnostics and status was visually weak. | Keep a concise healthy banner, individual service indicators and a final dedicated Updates tab. |

## Search, media and provider incidents

- Visible browser searches type at a bounded pace, verify focus and press Enter
  once. They share a local cooldown and never retry provider blocks.
- A Media request acknowledges immediately, runs one bounded first-result
  lookup, waits 1.5 seconds after a valid result and opens enabled Brave or
  enabled Firefox as fallback.
- File Search reads filenames and metadata only. A bare files/documents request
  asks one local follow-up; document scope stays inside `~/Documents`.
- CAPTCHA bypass, network rotation and simulated browsing were explicitly
  rejected.

## Preserved V2 behaviours

- Personal commands, spoken names, app selection, shortcuts, models, voice
  configuration and private helper files survive updates and rollback.
- Native commands remain the fast path and Qwen remains a bounded fallback.
- App additions and saved spoken names update both Qwen's permitted actions and
  dynamic Whisper hints after saving.
- One combined tray replaces the historical second microphone icon without
  losing microphone pause, restart, setup or maintenance controls.
- Media and File Search remain separate packages and entry points.
