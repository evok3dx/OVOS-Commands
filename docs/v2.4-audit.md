# Jarvis improvement audit

This is the living, privacy-safe audit for the V3 programme. Code and passing
tests describe current behaviour. This page records conclusions, constraints
and remaining evidence without reproducing workstation logs.

Status meanings:

- **VERIFIED**: confirmed by code plus an automated test or recorded live
  result.
- **PLANNED**: agreed but not implemented or not yet tested at its real
  boundary.
- **HISTORICAL**: an older approach retained only to explain a decision.

## Genuine improvements retained

- One tested focused-window boundary instead of app-specific assumptions.
- Atomic writes and private permissions for settings and personal phrases.
- A staged OVOS environment with permanent launcher relocation and full
  previous-environment rollback.
- Dynamic application discovery constrained by detection and user selection.
- Preferred app roles that never broaden into an arbitrary desktop launcher.
- Central action vocabulary, collision validation and a non-executing routing
  benchmark.
- Event-driven listening-cue handling with fresh volume snapshots and bounded
  restoration.
- Dynamic, size-limited Whisper app-name hints applied only to a recognised
  plugin source.
- Accurate reading outcomes and reversible temporary speed changes.
- One combined tray and lean GTK Control Centre with no local web service.

## Rejected over-engineering

- Rewriting the complete OVOS installer.
- Automatically chasing pre-release dependencies without compatibility
  evidence.
- A large application catalogue or arbitrary spoken executable/path support.
- A local web server for the Control Centre.
- Provider-evasion behaviour, automatic CAPTCHA retries or VPN rotation.
- Brittle screen-coordinate or assumed-Tab navigation for app fields without a
  stable shortcut or accessibility target.
- Placing a separate multi-model reviewer council in this desktop-control
  repository without an actual integration.

## Durable preservation boundary

Updates preserve downloaded models, OVOS configuration, microphone and voice
choices, app policy, preferred apps, personal spoken names, custom commands,
shortcuts and private extension helpers. Managed source, plugins, helpers,
units and launchers are transactional. Portable export is a separate,
privacy-filtered settings archive and does not claim to clone a machine.

## Historical incident summary

The V3.1 trial exposed gaps that a source inventory alone did not catch:

- copied virtualenv launchers retained deleted staging paths;
- a partial dependency upgrade left incompatible intent-parser versions;
- a TFLite wake path conflicted with the selected NumPy stack while ONNX
  worked;
- an opened but unusable microphone backend prevented fallback;
- cue timing and stale volume snapshots could clip audio or restore the wrong
  level;
- broad fallbacks stole unmatched commands and prompted replies;
- reading lock contention was reported as a launch failure;
- carried app policy could make every app selected or none selected.

Each cause, correction and regression boundary is distilled in
[the 3.1.1 incident record](v3.1.1-checklist.md) and
[the decision log](12-decisions.md). Raw machine logs are intentionally not
part of the public repository.
